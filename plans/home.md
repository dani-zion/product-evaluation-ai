# Plan: Home (product list)

Spec: [specs/home.md](../specs/home.md)
Wave: 1, runs in parallel with [sign-in](sign-in.md). [feedback](feedback.md) depends on this plan.

## Goal
Anyone, signed in or not, can browse every product on the home page. The list loads more products as the visitor scrolls. Clicking a product goes to `/products/{id}`, which [feedback](feedback.md) builds. External clients such as n8n create products with `POST /api/v1/products`.

## Decisions that fill gaps in the spec
| Topic | Decision | Why |
|---|---|---|
| Table name | `products`, plural. | It matches the existing `accounts` table. The spec says `product`. |
| `image` | `image_url text null`. It must be an absolute `https://` URL. Without one, the card shows a styled placeholder. | The spec left this as "?". |
| `score` | `score smallint null`, with a check of 1–5. `null` means "No evaluations yet". | It is the average of product evaluations. [feedback](feedback.md) keeps it up to date. |
| `external_link` | `text not null`, and must be an `http(s)` URL. | The spec marks `description` as optional but not this field. |
| Field limits | `name`: 1–200 characters. `description`: up to 2,000 characters. | — |
| Pagination | Keyset pagination on `(created_at desc, id desc)`. The cursor is opaque base64. `limit` defaults to 12, with a maximum of 50. | This stays fast and has no duplicates or gaps when new products are added while someone scrolls. |
| Who can `POST` | Requests need the header `Authorization: Bearer <PRODUCTS_API_KEY>` (a new env var). The key is compared in constant time. Without a valid key the response is **401**. | n8n can't hold a browser session, and an open write endpoint would invite spam. **Needs your OK.** |
| tRPC | Add only `products.list` (an infinite query) for the UI. Product creation is REST only, because no UI creates products. | — |
| Home content | Replace the landing page: remove `VerdictPreview` and "How it works" from home, as the spec asks. Keep `VerdictPreview` on the sign-up page. | — |
| Seed data | `supabase/seed.sql` with about 30 fictional products and no images, so the infinite scroll can be seen working. You apply it yourself. | — |

## Database
`supabase/migrations/20261121000000_create_products.sql`:
- Creates the `products` table with these columns:
  - `id text primary key`
  - `name text not null`
  - `description text`
  - `image_url text`
  - `external_link text not null`
  - `score smallint check (score between 1 and 5)`
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
- Adds check constraints matching the field limits above.
- Creates an index on `(created_at desc, id desc)`.
- Reuses the existing `public.set_updated_at()` trigger function.
- Enables RLS with no policies, so only the service role can access the table. This matches `accounts`.

## API
`GET /api/v1/products?limit=12&cursor=<opaque>`:
- **200** `{ items: Product[], nextCursor: string | null }`. When there are no products, `items` is `[]`.
- **400** for an invalid `limit` or `cursor`.
- **500** `{ error }`.

`POST /api/v1/products`:
- Request body: `{ name, description?, imageUrl?, externalLink }`.
- **201** `{ product }`. The id is a nanoid generated by the API.
- **400** `{ error, fieldErrors? }`.
- **401** for a missing or wrong API key.
- **500**.

`Product` (camelCase in JSON):
```ts
{
  id: string;
  name: string;
  description: string | null;
  imageUrl: string | null;
  externalLink: string;
  score: number | null;
  createdAt: string; // ISO
  updatedAt: string; // ISO
}
```

## UI and UX
Follow the existing design system in `src/app/globals.css`: dark plum, the marker highlight, Bricolage, left-aligned.
- **Page content:**
  - The page keeps `SiteHeader`.
  - Heading: "Products to evaluate" (or a sharper line from the frontend skill). It is followed by one sentence of supporting copy.
  - Below that is a responsive grid: one column on mobile, two at `sm`, three at `lg`.
- **Card:**
  - The whole card is one `<Link href="/products/{id}">` with a visible focus ring.
  - It shows a 4:3 image area. Use `<img loading="lazy" decoding="async">` with `object-cover`, because the host of an arbitrary image URL can't be listed in `next.config` ahead of time.
  - It shows the name, clamped to 2 lines, and the description, clamped to 3 lines.
  - It shows the score as "4/5" or "No evaluations yet".
  - Without an image, show a placeholder made from plum tokens with the product's first letter in the display font.
  - Cards are not raised or animated on hover. A subtle border colour change is the only hover effect.
- **Infinite loading:**
  - Use `useInfiniteQuery` through `trpc.products.list.infiniteQueryOptions`.
  - An `IntersectionObserver` sentinel loads the next page about 600px before the end of the list.
  - Also render a "Load more" button for keyboard users and for browsers where the observer fails. It is hidden while a page is loading.
  - A live region announces "Loaded N more products".
- **States:**
  - First load: 6 skeleton cards.
  - Empty: "No products yet. Check back soon."
  - Error: "We couldn't load products." with a "Try again" button.
  - End of the list: a quiet "You've seen every product."
- Read `node_modules/next/dist/docs/01-app/02-guides/` on data fetching and cacheComponents before deciding on a server prefetch. Prefetching the first page on the server is welcome if it stays simple. Otherwise fetch on the client with skeletons.

## Tests
- **Schema:** URL validation; `https` is required for the image; `description` is optional.
- **Service:** pagination order is stable; the cursor round-trips; the last page returns `nextCursor: null`; an empty list returns `[]`.
- **REST GET:** 200 with an empty array, 200 with a page, 400 for a bad cursor.
- **REST POST:** 201; 400 for invalid fields; 401 with no key and with a wrong key.
- **tRPC:** `products.list`.
